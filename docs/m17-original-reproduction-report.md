# M17 Phase 0–1 — Original W1 reproduction and configuration reconciliation

**Question.** Do the historical W1 speedups of 2.16× (Bulk 2×8K) and 2.54× (Bulk
2×16K) survive a stronger SIMT baseline, and what exactly produced them?

**Answer.** The three cells behind those numbers reproduce **exactly**: SIMT
270 753, Bulk 2×8K 125 581, Bulk 2×16K 106 456. But no single experiment ever
produced 2.16× or 2.54×. Those ratios divide a **κ = 0** SIMT number (270 753) by
**κ = 0.25** Bulk numbers (125 581, 106 456). Under a matched κ the same cells
give **1.753×** and **2.068×** at κ = 0.25, or **1.791×** and **1.913×** at
κ = 0. Both claimed figures are exactly 1.230× their matched-κ value, and 1.230
is 270 753 / 220 123 — the κ = 0 : κ = 0.25 ratio of the SIMT arm itself. The
whole discrepancy is the κ mismatch, not a modelling change, an estimate, or a
reconstruction.

Against a 128-MSHR SIMT front-end the matched-κ speedups are **1.748×** (2×8K)
and **2.112×** (2×16K): the 2×8K advantage is essentially unchanged (−0.5 pp)
and the 2×16K advantage becomes slightly *larger*, because the engine gains more
from the extra MSHRs than the SIMT arm does at that window size.

Every number below is measured. Tables are generated by
`build/wm/m17_extract.py` from `build/wm/m17_*.txt`; no value was transcribed by
hand.

## 1. The original experiment, located

The Bulk cells come from the M9/M10 three-arm driver (`experiment=m9diag`) as
used through M11–M15; the SIMT anchor comes from the same driver at a different
κ. Section 2 shows the SIMT arm is byte-identical under both drivers, so this is
one experiment harness, not two.

| quantity | original value | where it reproduces |
|---|---|---|
| SIMT-only, W1, N = 16 384, **κ = 0** | 270 753 | `P0_k0_w8192_s1`, `P3_k0_w8192_m16_s1` |
| Bulk 2×8K hybrid, **κ = 0.25** | 125 581 | `P1_w8192_m16_s1`, `P0_k0.25_w8192_s1` |
| Bulk 2×16K hybrid, **κ = 0.25** | 106 456 | `P1_w16384_m16_s1`, `P0_k0.25_w16384_s1` |
| 2.16× | 270 753 / 125 581 = 2.1560 | arithmetic only (§3) |
| 2.54× | 270 753 / 106 456 = 2.5434 | arithmetic only (§3) |

**No document in `DX100_MEM/docs` states 2.16× or 2.54×** (searched for the
strings and for the ratios). The two speedups are not published measurements;
they are ratios that can be formed from published measurements. That is the
central finding of Phase 0.

| parameter | historical | M17 reproduction | effect on the comparison |
|---|---|---|---|

| `N` | 16 384 | 16 384 | none |
| driver | `experiment=m9diag` | `experiment=m9diag` | none |
| `batch_window` (per buffer) | 8 192 / 16 384 | 8 192 / 16 384 / 32 768 | the capacity axis |
| `pool_slots` | 128 (diagnostic label) | 128 | display only: the slot pool *is* `R` = 128 |
| `cache_diag` | 1 | 1 | display only (§8) |
| `bulk_max_elems` | 262 144 | 262 144 | none |
| `seed` | 1 (published) | 1–5 | replication |

Parameters that are **not** interchangeable across milestones, and are treated
separately throughout M17:

* **`l1_mshr` vs `lsu_pending`.** The first is a per-core array of miss-status
  holding registers inside the L1; the second is a per-core cap on outstanding
  loads issued by the LSU. A request stalled at a full L1 MSHR still holds its
  residency slot; a request that `lsu_pending` refuses is never formed. §4 of
  the concurrency report shows they move the comparison in opposite directions.
* **`R` vs the 128-slot SlotPool.** `pool_slots = 128` is not a second budget:
  it is the diagnostic name for the same `R`, which is an *accounting
  abstraction* for "outstanding line requests", not a claim about native Vortex
  hardware.
* **`batch_window` vs total buffer storage.** `batch_window` is capacity **per
  buffer** and there are two buffers, so "2×8K" holds up to 16 384 entries in
  901 824 B (measured, §6).

## 3. The κ mismatch

The two families are measured at different κ, and κ changes both arms:

| κ | SIMT-only | 2×8K hybrid | 2×16K hybrid | 2×8K / 2×16K speedup | distinct lines |
|---|---|---|---|---|---|
| 0 | 270 753 | 151 145 | 141 559 | 1.791 / 1.913 | 16 384 |
| 0.10 | 251 124 | 141 208 | — | 1.779 | 14 853 |
| 0.25 | 220 123 | 125 581 | 106 456 | 1.753 / 2.068 | 12 636 |
| 0.50 | 169 826 | 94 035 | — | 1.806 | 9 319 |
| 0.75 | 120 110 | 95 194 | — | 1.262 | 6 376 |
| 1.00 | — | — | — | — | 4 096 |

*(seed 1; the full five-seed means are in `m17_tables.md` P3 and in the κ
report.)*

Forming 270 753 / 125 581 mixes the κ = 0 row with the κ = 0.25 row. The error
is not random: the SIMT arm is 1.230× slower at κ = 0 than at κ = 0.25
(270 753 / 220 123), so both cross-κ ratios are inflated by exactly that factor:

| claimed | value | matched-κ value | ratio | inflation |
|---|---|---|---|---|
| 2.16× (2×8K) | 2.1560 | 1.7528 (κ = 0.25) | 1.2300 | +23.0 % |
| 2.54× (2×16K) | 2.5434 | 2.0677 (κ = 0.25) | 1.2300 | +23.0 % |

The κ = 0 cell is also not a hybrid in the usual sense: dispatch routes every
element to the engine, so arm C and arm B are byte-identical there (151 145 /
141 559 in both). At κ = 0 the comparison is "all SIMT" vs "all engine"; the
hybrid only exists for κ > 0. This is a property of the existing dispatch
classification, not something M17 changed.

Seed 1 reproduces the published cells exactly: **220 123 / 138 924 / 125 581**

| W | L1 MSHR | seed 1 | seed 2 | seed 3 | seed 4 | seed 5 |
|---|---|---|---|---|---|---|
| 8 192 | 16 | 1.753 | 1.772 | 1.776 | 1.774 | 1.768 |

effect is not noise.

## 5. Effect of the stronger SIMT baseline

| configuration | κ | 16 MSHRs | 128 MSHRs | change |
|---|---|---|---|---|
| SIMT-only | 0.25 | 220 019 | 211 495 | −3.9 % |
| hybrid 2×8K | 0.25 | 124 406 | 120 988 | −2.7 % |
| hybrid 2×16K | 0.25 | 105 716 | 100 162 | −5.3 % |
| **speedup 2×8K** | 0.25 | **1.7686** | **1.7481** | −1.2 % |
| **speedup 2×16K** | 0.25 | **2.0812** | **2.1115** | +1.5 % |
| SIMT-only | 0 | 272 638 | 262 783 | −3.6 % |
| hybrid 2×8K | 0 | 150 952 | 148 822 | −1.4 % |
| hybrid 2×16K | 0 | 141 559 | 129 036 | −8.8 % |
| **speedup 2×8K** | 0 | **1.8061** | **1.7658** | −2.2 % |
| **speedup 2×16K** | 0 | **1.9260** | **2.0365** | +5.7 % |

Eight times the L1 MSHRs moves the matched-κ comparison by 1.2–5.7 %, in the
direction of the wider window. The reason is visible in the arms: at κ = 0.25 the
SIMT-only arm gains 3.9 % while the 2×8K hybrid gains 2.7 % (its engine is
already near the DRAM bound) and the 2×16K hybrid gains 5.3 % (a larger window
issues more concurrent lines, so it is the arm that can use extra MSHRs). The
2×8K advantage therefore shrinks and the 2×16K advantage grows.

## 6. Window naming, and why 2×32K is degenerate here

`batch_window` is capacity **per buffer**, and the engine has two buffers
(`src/sim.hpp`: `std::array<Batch, 2> bat_`). So 2×8K = 8 192 per buffer,
2×16K = 16 384, 2×32K = 32 768.

At N = 16 384 the stream has only 16 384 elements, so a single window of 16 384
already holds the entire trace. 2×32K is therefore **byte-identical to 2×16K**,
and the matrix shows it: all five seeds at both MSHR settings produce the same
cycles to the cycle. This is a property of the workload size, not a bug and not
an argument about capacity.

Measured realized window storage (exported as `bulk_win_vec_bytes`):

| configuration | realized storage | entries |
|---|---|---|
| 2×8K at κ = 0.25, N = 16 384 | **901 824 B** | — |
| 2×16K at κ = 0.25, N = 16 384 | **893 632 B** | — |

The 2×16K layout is *smaller* in realized bytes than 2×8K at this size, because
total entries are fixed by N and fewer windows means less per-window slack. This
is why the iso-storage comparison (§P5) uses the measured 901 824 B, not a
2 × 8 192 × 8 B estimate (131 072 B) and not the N = 65 536 figure of 933 856 B
from M16.

The non-degenerate capacity axis needs N > W; `P6` therefore repeats 2×16K vs
2×32K at N = 65 536 (κ report, §5).

## 7. Information that could not be recovered

| item | status |
|---|---|
| a document stating 2.16× / 2.54× | **does not exist** in `DX100_MEM/docs`; the ratios are arithmetic over two κ settings |
| the κ that produced 125 581 / 106 456 | recovered: 0.25 (§3) |
| the κ that produced 270 753 | recovered: 0 (the M5.1 published anchor) |

Nothing was reconstructed by guesswork. Every knob in §2 is either in
`configs/ab_controlled.cfg` or printed in the run's own configuration echo.

## 8. Verification

| check | result |
|---|---|
| historical anchors | 270 753 (κ = 0), 220 123 / 138 924 / 125 581 (κ = .25, W 8K), 220 123 / 107 146 / 106 456 (κ = .25, W 16K) — all exact |
| cross-driver SIMT check | `experiment=ab` and `experiment=m9diag` give the identical SIMT arm at both κ, for all three seeds: 270 753 / 272 903 / 273 615 (κ = 0) and 220 123 / 218 732 / 222 752 (κ = .25) |
| gates | every cell reports `M9 GATES PASSED` |
| output correctness | value hash matches expectation; `addr_mismatch = 0`; `dispatch_unaccounted = 0` in every cell |
| instrumentation neutrality | `cache_diag` is display-only; P0 (§8 of the κ report) and the M16 neutrality pair agree |
| regression suite | `./bin/dx100_tests` → 4 470 checks, 0 failures |

The `experiment=ab` cross-check matters because it rules out the obvious
alternative explanation — that the M9 harness changed the SIMT model between
M5.1 and M10–M15. It did not: the same workload at the same κ gives the same
SIMT cycles under both drivers, to the cycle.

## 9. Reproduction

```bash
cd DX100_MEM/sim && make -j4 && ./bin/dx100_tests     # 4 470 checks, 0 failures
bash build/wm/m17_matrix.sh                           # 490 cells, ~15 min
python3 build/wm/m17_extract.py && python3 build/wm/m17_plot.py
```

The two published cells, one command each:

```bash
# κ = 0.25, 2x8K → 220 123 / 138 924 / 125 581
./bin/dx100sim --config configs/ab_controlled.cfg --set rho_dup=0 --set elem_bytes=4 \
  --set bulk_wl=E0 --set bulk_max_elems=262144 --set max_cycles=200000000 \
  --set bulk_index_base=8388608 --set bulk_desc_line=98304 --set page_sched=1 \
  --set idx_mode=2 --set experiment=m9diag --set pool_slots=128 --set cache_diag=1 \
  --set Lambda=16384 --set P=512 --set bulk_stream=0 --set kappa=0.25 --set N=16384 \
  --set batch_window=8192 --set seed=1

# κ = 0.25, 2x16K → 220 123 / 107 146 / 106 456
./bin/dx100sim ... --set batch_window=16384 --set seed=1

# κ = 0 → the 270 753 SIMT anchor
./bin/dx100sim ... --set kappa=0 --set N=16384 --set batch_window=8192 --set seed=1
```
